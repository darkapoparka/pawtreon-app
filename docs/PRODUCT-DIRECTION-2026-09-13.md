# Pawtreon case-first product direction — 2026-09-13

This note records the owner's current direction and supplements the existing PRD/flows until those canonical files are regenerated or revised.

## Product model

Pawtreon is not an X/Bluesky-style social feed. The primary objects are animal cases, coordinated campaigns, donations/help requests, responsible organizers and progress updates.

A user may start a Pawtreon draft from an external X, Facebook or other source URL. That external post is source material only. Inside Pawtreon the result is a normal structured case or campaign, not a repost card and not a separate social-post type.

Source-assisted drafts must keep appropriate source attribution, avoid obvious duplicates, and must not import likes/repost/follower counts as trust signals. An external post does not prove permission to fundraise, beneficiary identity, evidence quality or payment readiness. Those checks follow the same review path as every other Pawtreon case.

Sharing goes outward from the canonical Pawtreon case/campaign URL. Sharing one case to several networks must never create duplicate fundraiser ledgers or duplicate totals.

## Discovery/home direction

The selected mobile reference uses: location at top left, centered compact paw-heart brand mark, account/avatar at top right, visible inline search, one quick-filter row, compact photo-led campaign banner, then `Cases near you` with animal-led cards.

Do not add a generic global statistics strip such as “animals helped” or “active campaigns” to the homepage. Counts belong where they answer a task, for example `48 results` after a search/filter is applied.

Map is a first-class alternate discovery surface and should share the same canonical location/filter state as the case list. Exact sensitive rescue/home locations remain privacy-protected.

The current visual reference tests a five-item dock: Cases / Map / Create / Messages / Campaigns. `Messages` is exploratory visual direction only; private messaging remains outside accepted v1 scope until the coordination, abuse-reporting and privacy model are explicitly approved. Account stays in the header/avatar.

## Search behavior

The inline search is visible in the initial home viewport. Do not also show a redundant standalone search icon there. During downward scrolling, avoid pinning the entire large header; a compact scroll-up/sticky search treatment can appear when useful.

## Trust rule

Mockup names, euro amounts, percentages, verification-looking marks, distances, campaign text and images are illustrative. They are not production data or evidence.
